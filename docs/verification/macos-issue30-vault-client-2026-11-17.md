## Selected path and source observations

The selected credential-bearing path is vault initialization/unlock, from the
original document's operation through the application-owned helper client and
back to an authenticated key. Previously retained dependency/XPC audits are
separate evidence and were not rerun as new progress.

1. `shell.rs::vault_prepare_initialize` / `vault_unlock` require the main
   window and a closed empty request. The document's vault methods decide
   availability and operation ownership. Main-window checks alone are not
   historical document-origin proof.
2. `asset_session_vault.rs::run_inner` reserves the initialization identity
   before obtaining `KeyringInitializationAdmission`. `InitializationKey` in
   `vault_crypto.rs` owns its generated bytes in `Zeroizing`; the renderer does
   not supply a wrapping key. Unlock carries only the stored vault identity.
3. `asset_session_keyring_macos.rs::gate` checks the same original owner/slot,
   allowed operation, original document lifetime, loss/STOP/lock/quit/retirement,
   phase and deadline. It is checked before client entry and independently for
   launch and GO. The post-join gate calls `interrupt` if eligibility has expired.
   These document gates were source-reviewed, not executed by the pipe fixture.
4. `vault_keyring_macos.rs::prepare` captures one clock bracket, creates a
   nonce, and encodes the request into fixed zeroizing transport storage. The
   native `vault_helper_launch.rs` adapter (read-only review) uses the fixed
   helper and working directory, `env_clear`, piped input/output/error, and only
   fixed gate arguments plus descriptor/PID numbers. Secret values are carried
   in the private input frame, not this argv/environment. No client temp-file
   route was found. This is source evidence, not a live helper launch observation.
5. The client sends once only after GO while no failure is latched, wipes the
   encoded buffer and request value, and rejects ambiguous/failed writes without
   retry. STOP before a complete request closes the retained input. Stderr is
   discarded into a wiped fixed buffer and becomes a closed `Protocol` error.
   Failed/mismatched output cannot become a decoded successful terminal.
6. `finish_driver`, `child_joined` and `consume_settled_key` separately require
   transport/native/pipe/process/worker finality and the original charge/deadline.
   `retain_authenticated_vault_key` rechecks the current document/operation and
   consumes a candidate to authenticate the exact vault header before retaining
   a key. An actual user-denial or installed peer response was not supplied.

The ordinary credential-input lane was also traced read-only:
`credential_prepare` -> bounded `asset_commands::prepare` -> document/context
gate -> `own_fields` -> retained `Payload`. `Fields` is write-only and zeroizes
owned strings on retirement. The shell drops its request before awaiting the
result; Tauri/renderer copies are outside that erasure claim. Existing tests for
that lane were not counted again as new evidence here.
