# Native Push observation — three fixed nonshipping cases

This packet adds Push siblings to the existing installed observer, not a new
runner. Apple reviewed the plan. Actual source review and native execution are
still required. Shipping CLT nomination remains **None**.

## Original route

The same observer chooses the task-created project, calls the real Connection
`connect_token`, waits for its joined result, observes Git, prepares Push,
explicitly applies that exact review, waits for the original receipt, disconnects,
and performs normal Quit. The existing GitLocal SourceBook, publisher, runtime,
FD8/C-A-W, journal/final CAS and NativeUse retirement stay authoritative.
No fake Connected state, native receipt, caller-supplied tool nomination or new
deadline is introduced. Nonshipping runtime selection binds the actual observer,
registered Document and the same protected runtime originals.

Only provider **bytes** are synthetic. The helper executes the original fixed
Push parser, body sender and command channel. Its sole send sink retains counts,
SHA-256 and the bounded command prefix, not a PACK copy. There is no socket,
real token, live account or remote mutation in this fixture.

| Case | Required behavior |
| --- | --- |
| `git-push-pack` | Real review dry-run/fixed hook, five GETs and no send; separately approved Apply sends one complete original body, parses status and the later advertisement. |
| `git-push-stale` | Apply advertises a different, setup-created OLD OID. Refusal precedes hook/ACK/POST; no retry. |
| `git-push-held-refusal` | The full original body is consumed. HTTP length/EOF are complete, but the inner receive-status pkt-line is truncated. The actual parser refuses; no later GET. The refused helper holds FD8 until the same original STOP or cleanup endpoint. |

Case C's fixed stderr marker is only a diagnostic trigger. The same driver must
independently see the original child/wait still pending and its receipt pending
before the observer stops that exact ticket. The helper's earlier first failure
is retained. Marker, exit code and result counts cannot supply EOF, joined jobs,
cleanup or finality. Any actual `CleanupUnknown` fails and retains custody. A
known cancelled/recovery result is never reported as successful Push.

## Fixed setup and retention

`macos_git_push_qualification.py` uses the existing `Fixtures` and `run_owned`.
It creates three tiny repositories under the native account's protected
Application Support ancestry with an empty Git template and cleared Git config
environment. Setup uses only fixed local CLT commands. Two ordinary commits and
one unreferenced comparison commit provide the three OIDs; no fetch/reset/server
or extra pack spool is used. One untracked file is deliberately preserved.

The held tool and complete original local object roster are checked before and
after. HEAD, current branch, index, tracking ref, both local reflogs, tracking
reflog, config and all six worktree files must remain unchanged. Unexpected files
are not adopted for deletion. The ordinary fixture owner retains failures and
unreturned callers; OS shutdown is not protocol settlement.

Bounds remain 120 seconds per case, 600 seconds total, 160 setup calls and five
seconds per call. Push itself keeps its existing 45/55 and first-F endpoints.
The transcript is at most 4 KiB with three OIDs; extra helper acquisition is at
most four leases/64 calls. Native/source and fixture cells are charged to the
same admission, with a conservative additional 1 MiB observer quote inside the
existing Push 200 MiB cap, not a quota increase or an RSS claim.
