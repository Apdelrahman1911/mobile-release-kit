This is a passive discovery and local-edit slice, not another runner. Apply
`project-scripts-hooks-20261020.patch` to the current Root integration together
with the six source/test leaves. It adds seven small shared hooks; no native

## Actual flow

1. The original snapshot walk admits fixed conventional `.sh` names in the
   root, `scripts`, and conventional `app`, `androidApp`, `composeApp`, `shared`,
   `ios`, `iosApp` directories or their `scripts` subdirectories. Its existing
   no-link/nonordinary/private-tree refusals, 128-file/512-KiB-file/8-MiB-total
   limits and original time/descriptor ownership still apply. No second scan.
2. After the SAME reader's final check and successful close, copy only mode,
   uid and gid from its existing receipt for private classification. No extra
   file probe, permission change, source execution or script-body export.
   Platform hints come from the existing Gradle/Xcode source parser, never
   enabled configuration alone or a guessed KMP/CMP framework.
3. `scriptDiscovery` exposes at most 16 sorted public relative paths and fixed
   purpose/header/mode classifications. Partial or truncated lists stay
   incomplete. Exact `/bin/sh` or `/bin/bash` headers plus applicable executable
   bits are necessary for a direct preset, not trust or runtime proof. Other
   headers, missing executable bits, special/shared-writable modes or missing
   POSIX metadata remain diagnoses. Windows does not invent executable rights.
4. Settings shows an optional script and explicit supported-stage choice.
   **Add to draft** only appends `['./relative/path.sh']` to the existing
   `projectChecks.*` list or fills an absent `ios.prepareCommand`. It never
   replaces that single command, removes an existing list entry, inserts a
   shell/arguments, or repairs malformed parents. The existing Advanced fields
   remain mounted and support manually reviewed commands/arguments.
5. The helper checks current service/epoch, exact project session/draft,
   original saved comparison, catalogue, platform, pending/picker/recovery
   gates. The original `edit` reducer's optional `expectedSession` check occurs
   **after** synchronous owner-retirement listeners; newer drafts/projects
   cannot be overwritten by an earlier append. Ordinary manual edits are
   unchanged. App's Boolean dispatch result describes only that local edit.
6. The same **Review & save…** review/apply owner remains the sole file writer.
   Later project checks/archive/artifact checks retain their own source,
   consent, argv, cancellation and finality requirements. No command runs on
   reading, selecting, adding, saving, mounting, refresh or retry.

`projectChecks.preflight` runs during explicit local-project checks/release
preflight, not every standalone build. The iOS preparation field and artifact
check fields likewise keep their actual existing stage meanings; there is no
invented general Android pre-build hook. Other layouts/headers are manual.

The separate accepted optional-`setupAnalysis` parser fix is prerequisite
`372006dc`. This successor adds only strict optional `scriptDiscovery`, matches
its partial bit to the same snapshot, and compares its finite classifications
for external changes. Unknown fields or malformed/authority-claiming DTOs
still refuse. Neither snapshot is an atomic or ongoing source guarantee.
