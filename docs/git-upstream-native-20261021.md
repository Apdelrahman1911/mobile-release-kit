# One installed local SetUpstream case

Source-only addition to the **existing** installed observer, Fixtures, original
`run_owned` caller and current-runtime driver. It is not a new harness or a native
qualification claim. Shipping availability, Git nomination, permissions, helper
bootstraps, source/process owners and operation deadlines are unchanged.

## Exact journey

`git-upstream-native` selects only `git-upstream-local`, and only a current
source-selected `git-native` observer image admits that scope. The existing job
runs its three remote-fixture invocations first, then this fourth explicit local
invocation in the **same installed image and unchanged 25-minute step**.

1. Existing Fixtures makes a fixed public project under the genuine native
   account's protected `Library/Application Support`, keyed by compiled
   source/run/attempt. Its ordinary protected CLT Git original creates two local
   commits with an empty template, explicit fixture-only name/email and a
   core/user-only config. Init's actual returned bytes (including optional
   boolean `ignorecase`/`precomposeunicode` probes) are bounded and retained;
   they are never assumed equal to the pre-init seed or rewritten afterward.
   No remote command, token, provider or GitHub session.
2. The same original project picker and snapshot precede real GitRead Observe:
   attached `main`, exact actual HEAD, and **not-configured** tracking.
3. Ordinary SetUpstream Prepare yields its actual joined ReadyReview: four
   approved config additions and four absent reference/log parent directories.
   Apply consumes that review through the unchanged Candidate CAS, native
   exclusive mkdir/retained-parent checks, digest ACK, config publication,
   SourceBook/worker/jobs/final-CAS/NativeUse retirement.
4. Native fixture comparisons require the exact original config byte prefix,
   approved suffix against that exact post-init prefix, new config inode with preserved mode/uid/gid/device, and
   only the reviewed directory successors. HEAD, index, branch, logs, project
   files and untracked sentinel remain unchanged. Tracking ref/log remain absent.
5. Fresh real Observe reports **gone** tracking, not remote availability. Second
   Prepare returns the identical complete configuration as **unchanged**. The
   observer calls existing Close/discard only: no second Apply or implicit Fetch.
   The post-Apply snapshot must still match. Normal Quit/relay return supplies
   the original finality; only then can the fixed report succeed.
6. After the real process return the outer existing owner independently compares
   the complete bounded Git tree, including every original loose object and
   `COMMIT_EDITMSG`. It rechecks the held CLT/native-parent originals and current
   installed runtime. Completion follows all original fixture closes.

The local comparison Control is registered to the exact original Observation and
Document before startup. It does **not** bind a runtime override or reuse a Push
Control. The existing Document census counts its bounded record/fixture data and
visits the actual retained picker/Quit originals via the same deduplicating
`Census.owner`, after releasing the session-book lock. No quota or history credit.

## Bounds and prerequisites

- Same **120-second setup + case** endpoint; setup receives at most 5 seconds per
  existing owned call, and the app receives only the remaining case time. The
  native observer retains its existing 120-second maximum. Ordinary Git work/hard
  endpoints remain **45/55 seconds**; no worst-case-sum extension or retry.
- Seven fixed setup Git calls, within the unchanged finite 160-call fixture
  ceiling. At most 128 Git tree entries, 64 entries per directory, 64 KiB per
  fixture file and 512 KiB total retained Git file bytes. No PACK or network.
- Requires the current signed/installed ARM observer, its original admitted
  Python/core/runtime/manifest, protected CLT and existing normal-user/AX/session
  prerequisites. Failure/unavailability/unknown is failure, never a passed case
  or synthesized original. No service/credential installation is performed.
- Source/account namespace collision, partial effect, lost caller, source drift,
  malformed report, runtime POST or close failure retains the existing original
  failure/custody and prevents completion. This is neither crash recovery nor
  broad Git/network qualification.
