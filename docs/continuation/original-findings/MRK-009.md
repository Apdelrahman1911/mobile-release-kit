### MRK-009 — Medium — dSYM validation ignores nested binaries

- **Affected:** `src/mobile_release/ios.py:785-880`; documentation at `docs/lifecycle.md:71-75`.
- **Trigger:** The app contains frameworks or extensions with missing or mismatched dSYMs.
- **Expected:** Every shipped Mach-O UUID has corresponding retained symbols.
- **Actual:** Only one main `.app.dSYM` is inspected.
- **Evidence:** An archive with a nested framework and no framework dSYM returned `ios.archive.dsym=PASS`.
- **Impact:** Framework and extension crashes may be unsymbolicatable despite a passing “exact dSYM” result.
- **Correction:** Inventory every shipped Mach-O and compare the complete UUID set with all retained dSYM DWARF binaries.
- **Verification:** Cover frameworks, extensions, multiple architectures, duplicates, and missing symbols.
- **Blocks:** iOS candidates using nested code with symbol retention.
