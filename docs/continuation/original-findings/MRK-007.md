### MRK-007 — Medium — Profile authorization is not checked for all entitlements

- **Affected:** `src/mobile_release/ios.py:323-405,543-574`.
- **Trigger:** A main app or extension contains an entitlement such as associated domains that is absent from its embedded profile.
- **Expected:** Every signed entitlement must be authorized by the profile.
- **Actual:** General subset comparison is absent; only identity/debug and APNs/iCloud environment properties receive semantic checks.
- **Evidence:** An app-only `com.apple.developer.associated-domains` entitlement was accepted.
- **Impact:** The validator can claim profile authorization for an entitlement set it has not proved.
- **Correction:** Implement profile-aware entitlement subset checking, including arrays, wildcards, application groups, keychain groups, and nested bundles.
- **Verification:** Add unauthorized, wildcard, array-subset, debug, and nested-extension cases.
- **Blocks:** iOS candidate validation.
