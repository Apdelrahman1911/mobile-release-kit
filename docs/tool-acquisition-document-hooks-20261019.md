Source only. No live download, native cache/GO/FD qualification, installation,
or iOS build success is inferred from this adapter or its DATA tests.

## Apply together (Root-owned central files)

- `tool-acquisition-central-hooks-20261019.patch`: actual Bridge owner creation;
  narrow Android original-document binding; saved-input lane/stamp accessor;
  source-proof retained-capacity traversal; new Doc child declaration; original
  Host/cache root merge at picker admission and independent cache check at final
  native project publication.
- `tool-acquisition-lifecycle-hooks-20261019.patch`: reciprocal peer gates,
  whole-Document context/loss/shutdown and exit joins. It does not propagate an
  unrelated single-owner relay loss/status mismatch as a fresh tools action.
- Root's `asset_session_tool_memory.rs` and `lookup_memory::tool_document_bytes`
  are separate reviewed source. Do not replace them with a model or DTO count.
- Root declares crate-root `mod tool_acquisition_protocol;`. Saved-owner native
  and cache children carry their supported-Mac/non-helper cfgs themselves.

The core patch's Host/cache merger returns a native root only if all present
original nominations agree exactly. Unknown/error is not absence. Root's small
Host noStore amendment may tolerate an extra genuine cache marker **only** with
the independent final cache validator in place. An active Host still needs its
own exact marker. No CLI grant/startup prerequisite is introduced.

## Native shell and closed requests

After the actual `DocumentBinding::new`, native shell setup calls once:

```rust
document.bind_tool_acquisition(&app.path().app_local_data_dir()?)
```

Keep unavailable if the native resolver/binding is unavailable. Do not fail
unrelated passive services or manufacture a fallback path. The owner still has
`NATIVE_QUALIFIED=false`; changing it requires separately reviewed actual Mac
profile/GO/cancellation/cache-tail evidence.

Use the ordinary same-window request envelope, `tool_acquisition_protocol`'s
bounded/strict parsers, then the real Document methods:

| Request | Parser | Document method |
| --- | --- | --- |
| status | `status_request(&Value)` | `tool_acquisition_status()` |
| inspect/prepare | `prepare(&Value)` | `prepare_tool_acquisition(Prepare)` |
| explicit Start | `start(&Value)` | `start_tool_acquisition(Start)` |
| cancel | `cancel(&Value)` | `cancel_tool_acquisition(Cancel)` |

`Action::Inspect` is the same real prepare/Start path without cache/network.
`Action::Acquire` additionally compares the SAME joined inspection and the
`pinned-public-tool-sources-v1` one-use explicit consent. Status/refresh never
renews consent. The private request contains saved bytes/hash and exact stored
comparison counters; no renderer path or JSON inventory becomes native input.

Relay `tool_acquisition_subscribe()` through the existing relay bookkeeping and
event `tool-acquisition-state-changed`; relay loss calls
`tool_acquisition_relay_lost()`. Retain original cancel/status after document
loss or Unknown. Root must add this relay to actual relay shutdown/join census,
not just spawn a detached event forwarder. On native saved observation, retain
existing version/inspection DTO semantics: only the original returned lane is
borrowed internally, never a renderer-shaped saved-binding object.

## Admission order and actual source

Prepare holds Doc, checks ordinary peer/registration gates, captures genuine
selected root plus full `native_roster`, obtains the original tool census,
then borrows the Edit guard and same returned saved lane. The private Arc input
is stored in that exact prepared Intent. All input/roster/lane capacities are
charged by T at Start; bounded temporary copies fit the unchanged fixed public
work reservation.

Start holds Doc; retrieves the actual prepared input; rechecks selected root,
full roster and counters; gets census and Root's same-state budget **before**
the Edit guard; rematches exact saved lane Arc/stamp/epoch/bytes; then consumes
consent and admits the same saved owner's original child. Both guards are
dropped before GO. Owner/native currentness never relocks Doc/Edit.

Only the original SourceBook can establish physical app-data/project exclusion.
The cache retains it before probing, requires actual Existing app-data and
rematches its parent and leaf on held native descriptors before any mkdir.
Post-effect root nomination requires original POST, one-close and all actual
joins. A later picker must independently re-probe this point-in-time identity;
no persistent-FD lease or reconstruction from a receipt is claimed.

## Existing limitations

- Actual admitted empty known catalogue/sources/pristine registration only;
  nonempty or recovery cases use existing reuse/inspection/manual flow.
- Existing app-data required; absent app-data remains unavailable.
- Strict physical native path (no lower symlinks/alias fallback) and bounded
  full registered roster. No whole-computer scan.
- Returned staged folders still require ordinary picker/Inspect/Review/Register
  protected copying. No source-origin synthesis or automatic registration.
- Framing/buffer reservations are not Python DOM/RSS or opaque native-heap
  bounds. Existing owner deadlines and cleanup semantics are unchanged.
