## Reachable operation

In the existing Advanced CLI tool controls, choose **Inspect saved
requirements**, review the saved project and effects, then separately approve
one Allow. The existing `mrk tool-setup-submit PROJECT INSTANCE GRANT REVIEW
--reviewed` command may perform one ordinary Prepare followed by Inspect.
Status/Stop use the same original request IDs. There is no new CLI verb,
service, namespace, pool, transport, permission family or native executor.
The original five choices and their required Prepared/source reviews remain.

This removes the otherwise necessary Desktop Prepare click. It does **not**
read saved inputs automatically, refresh the catalogue, choose sources,
acquire missing tools, register tools, or activate an unqualified runtime.
The saved-input observation, native catalogue, current project registration,
READ permission and installed Desktop must already be current. A later
acquisition still needs the genuine native Inspection and its separate
unchecked download consent; a service summary is never that authority.

## Original source and lifetime

* The new six-field Review is `inspect-saved-requirements`, Android, current
  draft/baseline, required `prepared:null` and `sources:null`. MAIN Allow's
  existing `sourceContext` is the exact validated ToolAcquisition Context:
  current project/hash/length, Inspect, required `review:null`. No CLI path,
  arbitrary source, draft, URL, license or extra action is admitted.
* Both Allow cuts compare the same saved lane Arc, original Context, complete
  registered-root roster, native registration, Doc and Edit stamp. The native
  retained Context hash/length also match the original service SavedPoint;
  the second cut rechecks its current revision/READ, not a later observation.
  Actual Prepare repeats the comparison and reuses that same input Arc.
* Known/CatalogLoan capture and the complete original census still occur at
  the existing Prepare site, before its Edit guard. No successful metadata
  comparison supplies a missing native source/loan/qualification.
* Only this new kind supplies a closed optional Tool `Preparation` to the
  existing generic Prepared constructor. Its actual Inspect Intent/link is
  installed before the original registry bump/notification. No public latest
  status is adopted and no early `NativeLink::entered` is fabricated.
* Prepared expiry is clipped to the original Allow/READ endpoint. Native Start
  uses the original Entry submitted time; existing 1200/1210 and earlier
  first-failure/READ endpoints are unchanged. No phase renews a grant/clock.
* A retained capture marker plus exact Created binding distinguishes known
  pre-Prepared refusal from committed/uncertain work. `!has_entered()` alone
  never proves no Prepared. Revoke after Prepare but before Start retires the
  same original registry Intent and reports its real identity. Actual native
  retirement, original relay return and history ACK are still separate cuts.
  Failed/lost calls and failed closes do not authorize a replacement/retry.
* Existing complete Doc and Tool admission charge the retained source,
  contexts/roster and binding capacities. No cap, census credit, qualification
  bit or existing runtime policy is changed. Root's separate shared Document
  capacity repair is not part of this packet.

## Renderer boundary

The existing ToolAcquisition Attempt is predeclared before Allow callbacks.
It records a service origin, never fictional GUI Prepare/Start calls. Early
matching native IDs are provisional DATA only; they cannot authorize another
operation, automatic cancellation of a foreign original, or completion.
A direct/reentrant second delegation cannot replace a pending origin.

The original Allow Promise must actually return. A correlated late ACK after
concurrent Revoke can join that original without reviving the permission or
its retired display generation. Lost/malformed ACK remains unknown. Only the
existing original service check after native/caller/history settlement,
followed by a newly begun exact native Status read, can complete the UI
attempt. Same-byte lane replacement, source/project ABA and API loss cannot
restore an actionable Inspection. A never-invoked/unused permission instead
needs actual return and a fresh unchanged native baseline.
