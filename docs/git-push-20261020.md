# Ordinary Push through the existing Git owner

## Supported increment

The existing five GitLocal commands now have a closed `push` action. Review
contacts the selected GitHub account/repository, but uploads nothing. A separate
checkbox and Apply send the reviewed 1–64 existing outgoing commits once to the
existing configured upstream branch. No selected files are staged or committed.
The local branch, index, worktree and cached remote-tracking ref stay unchanged.

The exact local branch/HEAD, cached upstream ref/OID, complete outgoing commit
set, account/repository IDs, source observation/reference revisions and native
review remain bound. Equal, divergent, incomplete, unsupported, stale or
unconfigured history is refused. There is no implicit Fetch, force option,
reset, merge/rebase, arbitrary URL/command, repository hook bypass or credential
export. This is not the first push of a new branch: explicit branch creation,
upstream establishment and an absent-ref intent remain separate unfinished
increments.

## Original execution and failure boundary

* The same Doc/Edit, GitLocal admission, Host/NativeUse, fixed runtime,
  SourceBook, Supervisor and 45/55-second/first-failure clock remain owners.
  The selected Connection retains the actual original ticket before GO. Native
  token borrowing is private and current; an action/status DTO is not a grant.
* Review uses stock Git's dry-run through the same private view and fixed
  pre-push hook. The hook only compares. The helper requires `0000` and EOF,
  permits five fixed GETs, and cannot request a candidate, ACK or POST.
* Apply reserves the original schema-8 Preparing row in the existing
  GitOperations namespace. The fixed pre-push hook compares the advertised
  OLD/ref and local NEW/ref before the candidate CAS and actual joined ACK.
  Its exact expected-old update and the stock non-force checks are not replaced
  by a later read or a supplied receipt.
* The same FD8 channel has a closed Push phase arm, not an open Fetch mode.
  Helper authorization precedes the hook; the hook ACK precedes the body-send
  claim. Pack EOF precedes waiting for send authorization. Review cannot borrow
  this sequence. C/A/W, all-copy EOF and private input/output closes remain
  mandatory; Git exit zero alone means neither a valid receipt nor cleanup.
* Apply holds one exclusive 0600 body inode and its parent before helper
  writes. A bounded pack stream is sealed/read back and the **same FD** supplies
  one receive-pack POST. No filename adoption, second spool, generic bytes-body
  widening, redirects, retry, push options/certificate, extra ref update or
  Fetch protocol-v2 header is admitted. Original HTTP control/first-failure
  observations precede finalizers, including 429/unknown-close cuts.
* The helper's bounded status/after-read data is not native finality. Actual
  source/runtime/child/IO/manager/observer joins precede the same final CAS;
  the actual all-jobs/NativeUse retirement precedes the final Connection receipt.
  Partial send, missing reply, failed join or unknown close retains the original
  work and fence. No later status or read may replace an unresolved row.
* Schema 8 adds one typed Push arm; readers preserve schemas 1–7 and reject
  fields before their minimum version. Only a real Preparing CAS upgrades the
  version. No status-driven rewrite, second journal or pending-row eviction.

The existing connected prerequisite chain also remains usable: only an idle,
current, same-project Connection can coexist with local Observe/Status or the
explicit Fetch/Push action. All other saved-owner, history and peer gates stay
in place; ordinary local/CLI writes still require disconnection. Native GitRead
captures the original connection epoch and rechecks its project, registration,
account/repository pins, expiry and idle state at each original current check.
No token is borrowed for this local read. Retained failure diagnostics accept
only the original flat Review view or Apply's exact two-component transaction
view; a displayed path never authorizes reopening, cleanup or retry.

## Later read, not retry

After a **known, genuinely settled original** Push needs recovery, an explicit
button can start a fresh overview read on the existing GitHubActivity owner.
It requires the actual same Apply call to have returned, no pending original
calls/Unknown, and the same retained project/account/repository/branch context.
Cold history, supplied status and an earlier Activity result cannot enable it.
Reentry, source/account/branch drift or an ABA transition withdraws comparison.

Every unrelated peer, native, Connection and permission gate still applies.
An expired/retired/stale connection or unknown original remains unavailable;
this button does not reconnect or make stale account facts current. The read
rematches the exact account/repository IDs and branch tip using the existing
overview schedule. Missing, inaccessible, malformed or unconfirmed responses
are not evidence of absence. “Remote now matches intended” is only later read
DATA: it neither proves this Push succeeded nor clears its ledger, offers a
retry, restores consent or adopts a remote state as a local observation.

## Bounded ownership

Root explicitly approved the Push-only 200 MiB admission ceiling: existing
full code 128 + whole Document 16 + base writer 16 + shared helper 16 + parent
channel 8 + separate Push body/call backing 16 MiB. Checked additions retain
actual Doc history and source/runtime/Store/IO structures; no discarded-review
or alias credit and no global quota change.

The body quote is 24,000 pre-entered call cells × 512 B + 2 MiB remainder
(14,385,152 B), including 28 stat records, a 64 KiB stream buffer, bounded
advertisement/status and fixed hook records. Two additional actual Acquisition
leases (body and parent) enter the original descriptor roster. Disk has one
32 MiB body plus metadata within the 80 MiB staging bound, **not** Fetch's pack
and index alongside another body. These are admission/backing bounds, not an
RSS measurement or native qualification.
