## Usable scope

In the existing **Release history** panel explicitly Prepare Enroll, Verify, or Review candidate inputs. After that original Prepare invocation has returned, the collapsed **Advanced: let a local CLI run one reviewed history step** child offers an explicit **Check original permission** followed by a separate unchecked one-use approval. A cold permission view requires that Check to actually return in this same Desktop connection. Later genuinely returned MAIN Access, Revoke, or Allow revisions may be retained for a subsequent NEW acknowledgement; neither mounting nor an already-acknowledged Allow silently refreshes its revision. Allow does not start work. The user may then run only:

```text
mrk local-history-scope PROJECT_ID [--json]
mrk local-history-submit PROJECT_ID SERVICE_INSTANCE GRANT_ID REVIEW_ID --reviewed [--json]
mrk local-history-status PROJECT_ID SERVICE_INSTANCE REQUEST_ID [--json]
mrk local-history-cancel PROJECT_ID SERVICE_INSTANCE REQUEST_ID [--json]
```

The client prints its exact request ID before sending Submit. `requests` discovery returns retained LocalHistory input IDs with fixed `local-history-status`; this sibling shares Store namespace **5** and its joint **32** entries. Lost replies never license new Submit. No autonomous Prepare, candidate selection, enrollment deletion/repair, Keychain bypass, build, Store request, publisher, imported GitHub receipt or new permission owner is added.

Enroll/Verify preserve the native platformless Context. Android ReviewInputs omits `platform`, while iOS uses `platform:"ios"`; only ReviewInputs carries the originally selected UUIDv4 candidate. Explicit nulls cannot replace those omissions. The native selected action/candidate remain authoritative; the renderer Allow carries only kind, original operation/generation IDs, status revision, the original MAIN permission revision, and the exact four-way consent literal. There is no config, version, path, credential or material input.

The existing genuine project-scoped READ permission is required. Host lookup uses `version_reserve_point`'s stable project/root/READ binding, **not StorePoint or a saved-config prerequisite**. This does not make an unavailable native profile available. Enroll retains the original local journal/Keychain side effects and rollback limitation; Verify/input review retain their existing read owners. A completed candidate report is current-file comparison only, not the earlier build's finality or Store authority.

## DATA and memory boundaries

Public Report is a typed bounded projection of the SAME already-validated retired native result (one finite native encoding and typed conversion), not another local-journal parser. It contains at most64 unique history rows, and only a real current candidate-input report for an inputs-ready row; inputs-pending/settled-failure can return no input report. Exact current file names/hashes/limits and all three native limitations remain. No raw journal, Keychain value or filesystem authority is exposed.

RAW commands are at most1KiB with a32-node/depth4 pre-growth Seed. Public replies are at most24KiB. Actual report cell/heap and NativeData cell/heap are individually guarded at8KiB. The IPC route joins the SAME eight-worker response maximum; no extra eight replies are charged or assumed free.

The Store debit stays **2MiB** under the unchanged64MiB Doc cap. The History quote preserves every existing StorePreparation term and adds an explicit512KiB subquote:

```text
32 * 3 * 8192                               original mixed rows/callbacks
+ 8 * (4096 + 2 * 8192)                    original IPC term, not credited away
+ 2 * 65536 + 32768                         original conversion
+ 128KiB                                   original fixed native grants
+ 3 * 128 * 512 + 8192                     original GUI validation
+ 512KiB                                   bounded History extension
= 1,974,272 bytes <= 2,097,152 bytes
```

That extension independently covers64KiB native weak-comparison cells, three public-return trees (384 nodes *256 plus24KiB text plus8KiB typed result each) and three32-node RAW decode trees:507,904 bytes <=524,288. Guards use real `size_of`/checked arithmetic/capacities; neither wire length nor successful Node tests establish native fit. Original strong material/source backing remains in the existing Saved/Doc census. Service's concurrent Later4 extension must preserve its own existing96KiB Doc +32KiB Saved and8KiB mixed-cell guards, not borrow this History subquote. **Actual compiled combined fit is unverified and required.**
