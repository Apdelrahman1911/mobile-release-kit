## 1. Smallest useful reachability, not another workflow engine

Reuse the existing `github-submit / github-status / github-cancel` ID-only verbs, namespace9, **one shared 32-row Inbox and one permission**, original selected Connection and native supervisors. A user still chooses exact options and grants permission in MAIN. CLI submission performs the actual existing Prepare or Pending load; it is not a cached-status alias. A completed Prepare never submits its corresponding mutation. A second, explicit one-use MAIN approval of its actual returned review is required.

These twelve closed service actions cover the existing routes without multiplying each platform/stage into a separate subsystem:

| Service action | Original native operation and actual effect | Required original |
|---|---|---|
| `preflight-prepare` | `github_preflight_command::Prepare`: fixed provider GET checks | MAIN branch + Android/iOS/Both selection and current Connection |
| `preflight-dispatch` | `Dispatch`: at most the existing single workflow POST | actual unexpired private Preflight Consent + exact confirmation |
| `preflight-pending` | `Pending`: fixed local journal load, token-free GO | current same-account/repository/project scope |
| `preflight-observe` | exact `Track` **or** `Reconcile`, GET-only | one selected native record; kind and nullable run ID fixed before Allow |
| `release-prepare` | `github_release_command::Prepare`: fixed provider/config/version GET checks | MAIN branch/platform/full existing Selection + current Connection |
| `release-dispatch` | `Dispatch`: at most the existing single workflow POST | actual unexpired private Release Consent + exact typed confirmation |
| `release-pending` | `Pending`: fixed local journal load, token-free GO | current same-account/repository/project scope |
| `release-observe` | exact `Track` **or** `Reconcile`, GET-only | one selected native record; kind and nullable run ID fixed before Allow |
| `counter-prepare` | Publication `Prepare(purpose=version-counter)`: existing saved-source/Host-state facet + eight provider observations | actual current saved inputs, explicit existing base branch, current Connection |

| `counter-reconcile` | Publication `Reconcile` of exact Counter row; GET-only | actual joined Pending-read witness + selected Counter record |

Release covers **Android/iOS × candidate/external-testing/production-submit**, including the existing valid recovery selection/confirmation forms, not Both. Preserve required-null fields, exact source/version/run lineage, real configured destination (including custom Android external tracks), publisher/caller pins and `matches_review`. Preflight is **not harmless**: its existing confirmation says it may build project code, download dependencies, consume hosted minutes and upload diagnostics. Release can sign/upload/promote/submit through the protected workflow. Preserve the existing mutable-branch/authorized-writer warning; dispatch is not an atomic commit lock. Counter means FIRST creation only: saved numeric initial version is not a Store floor; known prior counters/authority refuse, a competing ref must not be overwritten, and no allocation, enrollment, protection change, reset or Store request is authorized. No automatic setup, retry, polling, remote-run cancellation, environment change or Git transport.

The original seven service kinds/CLI bytes remain unchanged. Ordinary five-file Setup **Prepare** remains Desktop-owned (Publish/Reconcile already delegated); this plan adds its shared Pending loader only because Counter uses that same real journal. No remote-settings, release-dispatch policy rewrite, arbitrary Actions workflow, artifact download, resolver or local Store-engine work.

## 2. Exact input, permission and lineage

Extend the existing native MAIN Allow adapter, not CLI arguments. Native-only preparation inputs use the actual Preflight/Release/Publication argument types and existing validators; the installed CLI/shared protocol receives only compact typed references/results, never native input/material types. MAIN supplies branch/platform/Release Selection or Counter base, session/revision pins, and for Release Dispatch the same typed confirmation from the existing controller. Native resolves account/repository IDs, root/device/inode/generation, project binding, saved Edit/input epoch and actual credential end. It retains the exact bounded command capture on the original family state, with a weak reference to the shared scope. No public digest, ID or boolean constructs a private Consent.

The maximum valid Release Prepare options exceed the old 1KiB MAIN Allow envelope. Use **a closed new-Prepare-only 4KiB MAIN decoder bound**, direct typed deserialization, then the existing argument validation; old Allow variants and all CLI/IPC Submit/Query/Cancel remain at 1KiB. Other handlers remain unchanged. No global frame or resource-cap increase. UI copies only these new options under the same explicit bound and validates their exact shape; no generic Value/blob input or silent field truncation. No new endpoint is needed; preserve the existing four MAIN handlers, AppManifest/MAIN ACL and typed Tauri replies.

Every new kind has a distinct `agent-<kind>-once-v1` consent. Prepare/Pending/Observe grants have `none` effect and cannot authorize Dispatch/Create. Mutations start `not-sent`, become `potentially-applied` only on the same original GO, and keep their existing accepted/counter-observed/unresolved meanings. Observe retains an explicit track/reconcile discriminator, marker, complete native-record hash, and original known-run identity; it cannot change modes after approval. Dispatch/Create references contain the complete original Prepared digest and private identity, not merely its display marker. Release confirmation, platform/stage/recovery and Counter purpose are rechecked at native review, install, command entry and GO.

Reuse the current **MAIN permissionRevision** protocol without weakening it: Access and counter under the same Doc lock; a joined Check and fresh explicit ACK capture canonical full-u64 revision before listeners/async work; both Doc cuts compare that supplied original, and the checked successor is consumed before fallible installation/response handling. Empty/cross-kind/relay/READ revocation still advances it and stops originals even on overflow; MAX refuses Allow. No late status or failed/lost Allow rearms; no Doc or Book is held across Service/Host IO. This is a required narrow correction, not an assertion that current code already has the order: current `service_github_action_native.rs` stores the successor after `Inbox.allow` and the native install. Move that SAME store, under the final Doc lock after all currentness checks, to immediately before the first `Inbox.allow` call that can install a grant. A later Inbox/native-install/response error must still leave N consumed; retain and stop/close the exact possibly installed scope, never retry N. No additional epoch or registry.

A returned Prepare creates only the existing native private Consent, with a fresh identity and an optional weak link to its generating service Entry. Taking it for either GUI or a later CLI action requires that generating Entry's **actual native return + relay return + history return** all completed positively, not an early event. The producer link is a DISTINCT `Weak<Entry>`, never the existing consumer `agent: Weak<NativeScope>`. Its positive query requires the exact matching operation with `Admission::Returned` (not NeverAdmitted), successful native fact, actual relay return and final history ACK/no outstanding claim or Unknown; it does NOT call the old retired scope's `current(false)` or treat a completed producer READ as future authority. New permission/READ and native source gates supply future authority independently. Cancellation/revocation of an already completed Prepare cannot erase a successor capture; only that successor's own current scope or actual source/context expiry may stop it. The old Prepare grant is never reused. Keep the existing native consent expiry, clamped by the original credential/READ authority; a new grant cannot extend it. Add only a bounded private `positively_returned` query over existing Entry facts, not a new receipt or history layer. Normal GUI-prepared reviews retain their existing path.

For workflow records, retain one native-issued record witness on the original family state after an actually joined matching Pending/Dispatch/Observe acceptance, with original operation, scope/current revision, source stamp, record-set digest and end. Selection borrows the exact native row and hashes its complete Prepared/run identity, not the compact CLI view. Unknown/no-current accept cannot mint that witness. Publication reuses its existing `PendingRead`, adding a **Counter-only** selector alongside its unchanged Setup-only selector. The generic Pending target stays Setup-shaped as required by the actual protocol; no invented Counter Pending wire.

## 3. Same native caller, GO, retirement and clocks

Split only the two existing public name/value adapters into GUI wrappers + typed private `*_execute(command, optionalEntry)` as already done for Activity/Publication. Add optional Entry facets to the **existing** Preflight/Release gates and record captures to their own states. Before original admission, currentness checks match the exact installed scope/capture; immediately before `Supervisor::admit`, mark the same Entry entering. Extend the existing `supervisor_github_action_delegation::entry` selector to these two gates so the same Owner arms it **before any spawn/GO**. Native GUI entry cannot consume a delegated capture or Consent. No new supervisor/ticket/task channel.

GO retains original readiness/request digest, account/token, registered root/generation, publisher, branch/config/version and durable-journal checks; only then does the same Entry record its GO. Original Preflight/Release helper creates/validates its journal intent before readiness. A sent/lost dispatch never grants resend; Track/Reconcile inspect the original marker/run only. Cancellation during Pending/Observe stops that same caller and still owes every reader/writer/child/native close. Local Stop does not cancel a GitHub run or undo the Counter's entered tree/commit/ref claims.

**Use actual current clocks:** Preflight/Release Supervisor uses `OPERATION_TIME=10s`, `CLEANUP_TIME=2s`; do not replace it with Publication's 60s. Publication keeps its existing `min(start+60s, credential end, consent end, agent end)` and original cleanup. Same shared 100ms watcher samples the immutable READ end/earliest STOP, including after STOP until settled/Unknown. No new timer/renewal on event, queue receipt, read response, retry or history return. The permission's ≤120s admission expiry is not extra running time.

Append service completion only at the tails of the actual `accept_preflight / accept_release / accept_publication`, **after** same Connection `apply_control`, currentness, definitive reason/effect, native retirement and all early-Unknown handling. Never publish service success from a raw settled ticket. Keep the existing Entry's independent relay-return + native-return + history-ACK cut; a known pre-enter refusal uses `NeverAdmitted` only after actual relay/history return, not invented native retirement. Unknown/failed history remains absorbing. Retain pending-marker/effect diagnostics even when a successful payload is cleared. Service requests are reconnectable by their exact ID; a later row cannot stand in for the original.

Counter's real app-data requirement is not optional: extend the **same retained shell relay** call to pass only `app.path().app_local_data_dir()` (as existing Reserve/GitIndex ticks do) to Counter Prepare/Create; ordinary actions preserve their current no-path behavior. No CLI/environment/path argument, capability copy or reconstructed Host location. Failure to resolve the path refuses Counter before entering. Existing `Facet::new → reserve_native_state_location → begin_native_state_until` owns all source/Host/StatePort jobs and native proof; all three job handles, consuming closes and retained proof remain on the original Publication owner. Counter Prepare may establish the existing private service/state location; do not describe it as having no local effects.

## 4. MAIN/controller adoption, compact output and accounting

Extend the same collapsed Advanced permission panel across existing Preflight/Release/Counter controls. The original options forms, warnings, actual returned review, typed Release confirmation and Check/Stop/Close remain visible; no second permissions controller. The new Prepare/Pending delegate captures the exact current controller observer/API/options/source identity **before** synchronous listeners, then rechecks original context/revision/peer/revoke afterwards. Pending, reading, unknown and conflicting peers are not exempted. Exempt only the exact selected original, using refs initialized before controller constructors.

Never forge an ordinary GUI `Pending.sent`/Start-return receipt for a CLI operation. A distinct agent-origin tag inside each original controller tracks the shared request. After its exact service terminal has genuinely returned, a separately joined original native Status/Check must match operation ID, kind, context, options, Prepared/record digest and latest observer before that controller adopts its real native review/records. Require the generating Entry's positive cut natively too. An earlier event, unresolved GUI call, response from an old port, missing/changed result, or native Unknown cannot release/adopt. Failed/lost Allow delegation is monotone; only original unused/revoke/Check returns can retire it. A new mutation requires another joined permission Check and new ACK; no auto-submit/auto-dispatch.

Public service output stays historical DATA. Use a mutually exclusive tagged compact result in the existing **one result slot per shared row**, alongside unchanged Activity snapshots: Prepare receipt (original operation/marker/digest and bounded source/platform/stage); Pending list (at most64 marker/run-ID/purpose entries); observation (marker/exact run/attempt/status/conclusion or Counter commit/ledger/genesis digests). No tokens, raw config, ledger bytes, private paths, full Prepared, full job list or copied 64-row native journal. A Pending result does not expose authority or reconstruct an intent. Full reviews stay on their actual native controllers. Reject output that cannot be represented; never omit a row silently.

Keep the current **786432B GH retained debit**, shared32 rows and existing32×4096B snapshot allowance: each row can own at most one Activity **or** new compact snapshot, not both. Use fixed binary IDs/digests and numeric cells internally, serialize canonical existing public strings; assert actual Vec capacities/enum padding/string capacities/Arc headers ≤4096B and new response ≤8192B. Preserve old2KiB status shapes. Update real row≤16KiB/ancillary≤128KiB checks for all new capture/weak/typed/caller cells, including MAIN4KiB decode and overlap. All full native Prepared/record/capture copies remain in original Connection/Publication heap/census, not credited into the compact result. Publication retains its8MiB partition including existing Counter6MiB. Shared IPC remains the actual eight-worker O/M/H pool with one Metadata lease; update actual enum/validator ceilings, no new per-family eight-response debit. Full current Doc/native admission must still pass; if these fixed envelopes cannot fit actual code, report it rather than silently increasing caps or dropping retained originals.
