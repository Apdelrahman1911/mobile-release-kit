Before you install

If Mobile Release Kit is running, use Prepare app to quit when available, then quit the app normally. Do not force quit it to make installation proceed.

Run Install.pkg from its complete original disk image. Keep producer.json and producer.sig alongside the package. The installer checks which action can safely be performed at the fixed managed location; this page is not permission to replace or delete files.

If installation does not finish

Different failures have different causes. A generic Installer failure does not mean that recovery completed, or that an older package is necessarily required.

  1. Wait for Installer to finish before trying again. Keep existing installation and recovery files, projects and saved credentials. Do not delete managed folders or change their permissions to force progress.
  2. Recovery of an interrupted installation may require the same release's original Install disk image that was being installed. A newer installer cannot always repair an incomplete older installation. If the result asks for the original installer, obtain that exact release's complete disk image rather than guessing another version.
  3. To see details without Terminal, keep Installer open and choose Window > Installer Log (Command-L). In that window choose Show All Logs; use Save to keep a copy if you need support. Review a log before sharing it.
  4. If the required original package is unavailable, or a retry with the correct package still fails, stop and keep the files and log for support. Do not repeatedly try unrelated packages.

It does not replace Installer's actual success or failure result. A package log is diagnostic information, not proof that installation or recovery finished.
