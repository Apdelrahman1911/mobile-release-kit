Prepare Xcode for MobileReleaseKit

This separate package prepares a protected copy of Xcode. It does not install MobileReleaseKit, build an app, upload to a Store, or grant Store consent.

Before continuing

  1. Finish all builds and Store operations, then quit MobileReleaseKit before continuing. Beginning preparation changes the selected-tool namespace and may invalidate an operation that already observed its absence.
  2. Install full Xcode from Apple in /Applications/Xcode.app. Open Xcode and complete Apple's license, first-launch and required platform/SDK setup.
  3. Keep enough free disk space for a second full logical copy plus working reserve. Copying and verification may take up to about an hour.
  4. Use your normal administrator approval in Apple's Installer. The source must already be publicly readable/searchable; unsupported private files or access control lists cause refusal, not permission changes to your original Xcode.

What this package changes

The protected copy is /Library/MobileReleaseKitDeveloper/Xcode.app. Your original Xcode stays unchanged. This package does not change xcode-select, bypass an Apple license, download Xcode, or automatically update it. A tiny, nonexecutable package carrier is also installed at /Library/MobileReleaseKitXcodeSetup.bundle. Unknown existing carrier contents or inconsistent package receipts are refused before replacement.

If preparation is interrupted

Open this same signed package again. It can discard only authenticated unfinished setup work, or an authenticated empty pending wrapper after a completed copy. It never replaces or deletes a completed protected Xcode copy. Only an exact same-package carrier repeat is supported; unrelated or older/newer carrier state is not automatically repaired. A failed Installer result does not prove that an earlier operation or cleanup finished.

For details, use Window > Installer Log in Installer. Return to MobileReleaseKit after preparation and use its normal environment checks. Installer completion alone does not establish tool, SDK, archive or upload readiness; the app validates its own current tool originals on each operation.
