# Support

Mobile Release Kit is supported through
[GitHub Issues](https://github.com/Apdelrahman1911/mobile-release-kit/issues).

## Before you open an issue

- Search the [existing issues](https://github.com/Apdelrahman1911/mobile-release-kit/issues?q=is%3Aissue)
  to see whether the problem is already known.
- Check that you are using the latest release. Only the latest desktop release and
  the latest CLI toolkit release are supported.
- Read the [README](README.md) and the documentation in [`docs/`](docs/).

## Opening an issue

- **Bug:** use the *Bug report* template. Include your platform, app version,
  install method, the steps to reproduce, and what you expected and saw.
- **Idea or request:** use the *Feature request* template.

The desktop app collects no telemetry, so a problem is only known when someone
reports it.

## Keep secrets out of issues

Issues are public. Never paste passwords, tokens, API keys, keystores, signing
certificates, provisioning profiles, service-account keys or other credentials.
Replace personal paths, user names and machine names with placeholders such as
`<HOME>` or `<PROJECT>` in logs and screenshots before you post them.

## Security vulnerabilities

Do not report a vulnerability in a public issue. Follow [SECURITY.md](SECURITY.md)
and report it privately through the repository's **Security** tab →
**Report a vulnerability**.
